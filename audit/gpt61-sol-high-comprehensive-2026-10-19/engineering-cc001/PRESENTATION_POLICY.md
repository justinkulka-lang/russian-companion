# CC001 presentation policy

Version: `sha256-option-order-v1`. For each option, sort ascending by lowercase SHA256 of canonicalParts([version, context, itemId, optionText]); break hash ties by option text. canonicalParts uses UTF-8 byte lengths, list counts and explicit separators. No answer key, correctness flag, learner history, current index, clock or platform random source participates. Option text and multiplicity are conserved; no generated native language or altered keys.

Lesson context: canonicalParts(["lesson", stepId]). Lab context: canonicalParts(["lab", labId]). Both are deterministic on restart/restore for the same reviewed item/context. Selections and grading remain exact strings. An existing lesson/lab first viewed on older app source changes to this new display convention on upgrade; older builds did not persist a presentation version. Previously selected values remain selected and credited by the existing identity rules. This change does not claim the old source's visual order is preserved across upgrade. Re-entering a task on this implementation preserves its order without storing an extra list.

New review context: canonicalParts(["review", assignmentId, slotIndex.toString()]). The response-rule digest binds the unchanged grading-rule digest, new presentation version, context contract and SHA ordering/tie-break. Assignment digest already binds responseRuleDigest. Each assignment thus retains the display rule and order through persistence/backup/reopen. Existing schemas1–6, policy definitions, recent-item selection and accepted-order semantics stay unchanged. New assignment IDs vary presentation even when the reading slot uses the same item.

Legacy saved review assignments retain their exact original response-rule digest, assignment digest, option order and value-based grading. They remain eligible only through the existing policy/content/teaching checks; no new historical credit is inferred. Unknown response-rule digests fail current assignment validation; helper returns no choices. Existing structural backup validation still conserves historical unknown rule hashes without calling them current.

The preserved legacy review display is an explicit compatibility exception to the bias correction. Deterministic permutation removes the overwhelmingly correct-first presentation; it does not claim equal counts at every position, unseen tasks, resistance to memorizing a specific task, productive competence, complete curriculum acceptance or an adequate assessment design by itself. Raw authored options remain biased because they are immutable source evidence; application display now separates their order from scoring.

Host Compose saved-instance-state restoration is a bounded surrogate; it does not recreate MainActivity, prove physical rotation, or establish Galaxy S26 Ultra airplane-mode/reboot acceptance. That acceptance remains LAST after the final independent comprehensive audit of corrected source.
